# Fashion Try-on Runner v1 Spec

**状态：** 方向已由用户于 2026-08-30 确认；本文是 v1 实现的唯一行为事实来源。
**范围：** 本地、Agent-first、文件夹驱动的 AI 批量换装 CLI 与配套 Skill。

## 背景与目标

旧 DSH 实现把批量换装放进右侧工作台、iframe 面板和女仆悬浮球，同时维护浏览器状态、服务器状态和固定“Agent 模式”。这使“给文件夹 → 批量生成 → 审核 → 落盘”的简单工作流承担了不必要的 UI 与宿主复杂度。

v1 建立一个不依赖 DSH 和浏览器的本地 runner：Agent 接收用户给出的素材文件夹，调用 CLI 完成预检、归类、裁图、定制提示词、出图、质检、有限重出、恢复与报告生成。用户主要通过对话操作，通过静态 HTML 审核结果。

## 关键行为

### B1 CLI Interface

CLI 可执行名为 `fashion-tryon`，提供五个命令：

1. `fashion-tryon preflight <input-dir> [options]`
2. `fashion-tryon run <manifest-path> [--answers <answers.json>] [--json]`
3. `fashion-tryon resume <run-dir> [--json]`
4. `fashion-tryon retry <run-dir> (--task <task-id>... | --review-failed) [--json]`
5. `fashion-tryon report <run-dir> [--json]`

`preflight` 支持以下 options：

- `--output-root <dir>`：缺省为输入目录同级 `<input-name>-tryon-output`。
- `--scope <top|bottom|full|full_acc>`：全局换装范围；分组可在 answers 中覆写。
- `--pairing <pair|fixedModel|fixedClothing>`：全局配对方式；分组可覆写。
- `--model <id>`：生图模型；缺省读 `IMAGE_MODEL`。
- `--vision-model <id>`：视觉模型；缺省读 `VISION_MODEL`。
- `--size <1:1|3:4|2:3|4:3|3:2|9:16|16:9>`：缺省 `3:4`。
- `--max-retries <0..3>`：质检失败最大重出数；缺省 `1`。
- `--json`：stdout 只输出一个结构化结果；诊断写 stderr。

退出码固定为：`0` 成功或 preflight 已 ready；`2` 需要用户回答、找不到可运行任务或 run 尚有未解决问题；`1` 配置、I/O、provider 或不可恢复执行错误。

CLI 不把密钥作为参数，不在输出中回显密钥。

### B2 输入扫描与归类

- 接受绝对或相对输入目录；解析后必须是可读目录。
- 输入目录全程只读，不覆盖、移动、改名或删除原始素材。
- 递归接收 `.jpg`、`.jpeg`、`.png`、`.webp`，单文件上限 64 MiB；空文件、超限文件和其他格式进入 skipped 清单，不静默丢弃。
- 忽略 `.git`、`node_modules`、隐藏的 `.tryon-*` 目录，以及本次 `output-root`。
- 目录结构优先于视觉判断。角色目录词表：
  - garment：`服装`、`衣服`、`单品`、`产品图`、`平铺`、`garment`、`garments`、`clothes`、`clothing`、`product`。
  - model：`模特`、`人物`、`人像`、`模特图`、`model`、`models`、`person`。
- 款级分组取角色目录的直接上级；没有角色目录时取最靠近文件的目录层。
- 没有角色目录线索时调用视觉分类。置信度低于 `0.70`、返回 `other` 或视觉调用失败的图片进入 questions，不硬猜。
- 同批重名文件使用稳定后缀 `_2`、`_3` 去重；任务和资产 ID 在同一 manifest 重建时保持稳定。
- 没有有效服装或模特配对的组进入 questions；不得开始付费生图。

### B3 Preflight 与少量提问

- `preflight` 创建唯一 run 目录并写入 `manifest.json`、初始 `state.json` 与 `events.jsonl`。
- 结构清楚且所有必需配置已有默认值时，结果为 `ready`，不制造问题。
- 只允许询问会改变结果或成本的问题：图片角色/分组、配对方式、换装范围、模型/尺寸、最大重出数。
- 每个 question 必须有稳定 ID、原因、允许答案和推荐默认值。
- `run --answers` 接收 JSON answers，验证 question ID 和答案范围后生成 resolved manifest；未知或遗漏的必答问题使命令退出 `2`。
- 任务预览必须给出首轮生成张数和考虑最大重出后的理论最高生图张数。

### B4 预处理与定制提示词

- 视觉调用前的工作副本压缩到小于 1 MiB，最长边不超过 1600 px，JPEG quality 默认 85；原图不变。
- 服装图有可信 bbox 时按已验证余量裁切：左右 `20`、上 `22`、下 `34`，以 1024 基准等比换算；bbox/裁图失败退回压缩工作副本并记录 warning。
- scope 为 `top`、`bottom` 时使用 single 模式，只替换目标部位并逐条保留其余可见服装。
- scope 为 `full` 时替换图中可见完整服装，但不凭空补图中没有的品类。
- scope 为 `full_acc` 时允许替换参考图中可见配饰，但仍不凭空补品类。
- 定制 prompt 必须包含：取什么、留什么、禁什么、姿势与场景、构图、光线。
- 服装图内容指纹与 scope 共同构成 brief/cache key；相同内容和 scope 不重复调用视觉模型。
- 参考图长度、构图或品类不可辨认时写入 uncertainty，不能用猜测填补。

### B5 批量生成、状态与恢复

- v1 生产生图 adapter 使用 APIMART：提交异步任务后每 3000 ms 轮询，单任务轮询上限 300000 ms，完成后立即下载结果 URL，不能把临时远程 URL 当最终产物。
- v1 生产视觉 adapter 使用 DashScope OpenAI-compatible multimodal endpoint，`max_tokens` 默认 8192；输出因长度截断必须报明确错误，不能解析半截 JSON。
- APIMART production 生成的安全并发上限为 `2`；新 manifest 默认写入 `2`，历史 manifest 即使记录更高值，CLI 的正式 `run` / `resume` / `retry` 也必须按 `2` 封顶。测试 fake 可显式覆盖，不改变账本兼容读取。
- transport retry 必须区分上传、提交、轮询和下载阶段。上传网络错误及明确返回的 HTTP 408/429/500/502/503/504 可重试；400/401/403/404、结构错误和不支持的模型不自动重试。
- transport retry 使用秒级指数退避与随机抖动：第一次等待 `2000–2999 ms`，第二次等待 `4000–4999 ms`；不同任务不得在固定 250/500 ms 后同步重放。
- APIMART 返回 `task_id` 后必须立即写入 task state 和事件；之后的轮询或下载失败只恢复同一 `task_id`，不得重新上传或提交生成。生成提交发生无 HTTP 响应的网络失败时结果不确定，不自动重提；错误必须记录请求阶段及可用的底层网络错误码。
- 配对方式为：`pair` 一一对应且两侧数量必须相同；`fixedModel` 第一张模特配全部服装；`fixedClothing` 第一件服装配全部模特。
- 默认并发 `2`；内部必须有一个共享并发闸门，不能由每组各自放大并发。
- 每个任务的输入、prompt、模型、尺寸、scope、状态、尝试次数、版本路径和错误都写入结构化状态。
- 每次状态写入使用临时文件 + 原子替换；进程中断不得留下半截 JSON。
- 已完成且输出文件仍存在的任务在 `resume` 时跳过；运行中/失败且仍有配额的任务继续；输入指纹变化时拒绝 resume 并明确指出文件。
- 每一轮生成图都保留，命名在单次 run 内不覆盖；最终采用版本由 state/review 指明。
- provider 的超时、限流和可重试错误记录标准化错误码；单任务失败不拖垮其他任务。

### B6 自动质检与有限重出

- 每张首图生成后自动比较服装参考图、成图和模特原图。
- 四个维度固定为：`completeness`、`fidelity`、`identity`、`quality`。
- 质检输出固定包含 `verdict: pass|retry`、结构化 issues 和 `fix`；`retry` 时 fix 不得为空。
- scope 必须同时驱动生成 prompt 与 completeness 判据，避免“只换上装”被按全身标准误判。
- `retry` 时把 fix 追加到原 prompt 后重新生成，最多执行 `maxRetries` 次；每次重出后重新质检。
- 达到上限仍不通过时保留最后版本并标为 `review_failed`，不删除图片、不伪报成功。
- `fashion-tryon retry --review-failed` 只重跑最终为 `review_failed` 的任务；`--task` 只重跑指定任务。手动重跑产生新版本，不覆盖旧版本。

### B7 产物与静态报告

每个 run 目录固定包含：

```text
manifest.json
state.json
review.json
events.jsonl
prepared/
images/
report.html
```

- `manifest.json` 是已解析的输入和任务计划；`state.json` 是执行状态；`review.json` 是质检结果；`events.jsonl` 是只追加审计流水。
- `report.html` 由上述结构化文件派生，可重复生成，不保存新的业务状态。
- 报告使用相对路径引用本 run 的图片，直接以 `file://` 打开可用，不依赖服务器或网络前端资源。
- 报告展示：run 摘要、成功/失败/质检未过统计、首轮与最高成本任务数、每任务服装/模特/所有生成版本、最终采用版本、prompt、质检 issues/fix、耗时与错误。
- 报告支持按 `pass`、`review_failed`、`generation_failed` 筛选，但 v1 不在 HTML 内直接调用接口或改写本地状态。
- HTML 和 JSON 中不得包含任何密钥、Authorization header 或完整 provider 响应头。

### B8 Agent Skill

- 提供 `skills/fashion-tryon/SKILL.md`，触发语义包括批量换装、文件夹试穿、服装图配模特和对换装结果做质检。
- Skill 先调用 `preflight --json`；仅把返回的 questions 集中问用户；ready 后调用 `run`。
- 长任务使用 CLI 进度/状态，不要求用户打开工作台。
- 完成后返回 run 目录和 `report.html` 路径；用户要求重做时调用 `retry`，不手写 provider 请求。
- Skill 不包含 API key、业务实现或旧 DSH 路径。

## Out of Scope

- DSH 右侧工作台、创作表单、女仆悬浮球、iframe 和浏览器存储桥接。
- 资产库、灵感库、Prompt Bank、人工裁图编辑器和可交互相册。
- MCP server、远程多用户服务、账号权限和云端部署。
- 通用场景生成、套图、换背景或“万能生图工作流”。
- 在报告 HTML 内直接重跑、修改 manifest 或写本地文件。
- 自动发布 GitHub、安装到 DSH 或替换旧插件。

## 验收标准

1. **结构化目录预检：** 两个款目录、每款含 `服装/` 和 `模特/` → 无视觉分类即可得到两个正确组，任务数与配对规则一致。
2. **无结构目录确认：** 混合素材 + fake vision 的低置信度结果 → preflight 退出 `2`，questions 完整；提供 answers 后 manifest ready。
3. **输入安全：** 超限、空文件和非图片进入 skipped；输入目录中文件 hash 在完整 fake run 前后不变。
4. **提示词口径：** top/bottom/full/full_acc 四类 fixture 产出的 prompt 和 review expectation 同 scope；图中没有的鞋、围巾等不会被补进 prompt。
5. **批量闭环：** fake providers 跑至少四个任务，其中一次限流后成功、一次永久失败、一次质检 retry 后通过、一次重出上限后仍失败；状态、版本、review 与统计全部正确。
6. **中断恢复：** 在部分任务完成后模拟退出，再 resume → 已完成且文件存在的任务不重复调用，未完成任务继续。
7. **选择性重跑：** `retry --review-failed` 只为未过审任务追加版本，原图和旧版本保留。
8. **报告：** Playwright 以 `file://` 打开报告，在桌面与 1280px viewport 可查看全部对照图、筛选和错误；无需网络请求。
9. **秘密安全：** 全测试、Git tracked files、run JSON/HTML 中均找不到 `.env.local` 中任何密钥值。
10. **Agent 调用：** Skill 能根据 preflight JSON 只问返回的问题，随后完成 fake e2e 并给出报告路径。
11. **真实链路门禁：** 只有用户明确授权且设置 `RUN_PAID_E2E=1` 时，才用 1 组素材跑真实 APIMART + DashScope；真实验证结果另存本地验收记录，不提交用户图片或密钥。
