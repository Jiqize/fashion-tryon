# Tryon Studio：按套批量换装与人工判断

- 状态：已确认
- 日期：2026-09-25
- 取代：v1–v5 的"命令流水线 + 指纹授权 + selection artifact"交互方式（运行内核中的付费与恢复保障保留）

## 1. 背景与目标

一批素材通常有 30–40 套服装，每套生成 3–8 张模特姿势图，一批约 100–300 张。现状的问题：

- 一批从开始到交付要经过约 11 个人工节点（问答、看预览、授权指纹、起审核会话、保存、说"审核"、多次 dry-run 与授权）。
- 必须等整批跑完才能开始判断，并发封顶 2，一批要跑一到两小时。
- 判断以单张为单位逐一"采用"，300 张就要操作 300 次。
- 现有界面（经典版与玻璃版）不好看，且玻璃效果会干扰对颜色的判断。

目标：**人的判断是唯一的质量关口，把判断做到最快**。具体来说：

1. 一批从拖入到交付，只需要三类人工动作：确认开始、按套判断、（可选）重出。
2. 生成和判断同时进行：一套生成完即可判断，一套判断完即可交付。
3. 判断按套进行，默认通过，只标记例外。

## 2. 输入结构与搭配模式

一批 = 一个素材根目录。根目录下每个子目录是一组，一组 = 一套服装，目录名即款号。每组内有 `服装/` 与 `模特/` 两个子目录。

三种搭配模式，整批选一个，也可以单组覆盖：

| 模式 | 组内素材 | 产出 | 典型用途 |
|---|---|---|---|
| **固定服装**（默认） | 1 张服装图（整套）+ N 张模特姿势图 | N 张，每个姿势一张 | 主场景：一套衣服出 3–8 个姿势 |
| **一对一** | N 张服装图 + N 张模特图 | N 张，按顺序一一配对 | 服装有多个角度，与姿势角度对应 |
| **固定模特** | N 张服装图 + 1 张模特图 | N 张，每件衣服一张 | 只需要单张 look |

- 模特图张数不设硬性上限，超出 3–8 的范围只提示，不阻止；固定模特模式（整批或单组覆盖）只有 1 张模特图，不提示。（2026-09-25 修订）
- 数量不符合模式要求（如一对一两边张数不同、任一边为空）的组标为"素材不全"，不进入生成，其他组照常进行。
- 输入目录只读。`成图/` 是唯一允许写入的业务输出目录，扫描时忽略它。系统伴生文件（`._*`、`.DS_Store` 等）自动跳过。

## 3. 关键行为

### 3.1 入口

- `fashion-tryon studio <素材根目录>` 启动本地服务（仅监听 127.0.0.1）并打开浏览器页面。
- 一个服务对应一批。开始新的一批用 `fashion-tryon studio <另一个素材根目录>` 另起（通常由 Agent 代劳）；浏览器无法取得本地文件夹的绝对路径，因此不支持在页面拖入目录。（2026-09-25 修订）
- 同一批关闭后重新打开，恢复到上次的全部状态（生成进度、判断结果、交付情况）。
- Agent 可以通过同一个 CLI 启动 studio 和查询状态，但不再承担授权与转交决定的职责。

### 3.2 开跑前：素材表

- 页面主体是一张"套 × 图"表：每行一套，最左侧显示服装裁后图，右侧依次是这套的模特图（配对关系一眼可见）。
- 每套服装自动裁图（沿用已验证的裁切规则）。用户可以在页面上手动调整裁切框，调整结果只作用于本批。
- 每套服装自动生成服装描述与提示词（沿用六段式结构），用户可以在该行展开查看，不需要确认。
- 裁切、服装描述或提示词生成失败的套在该行显示失败摘要与"重新准备"按钮，点击后重新准备，成功后该行恢复为可勾选开始。（2026-09-25 修订）
- 顶部可设置：搭配模式、换装范围（全身 / 上装 / 下装 / 含配饰）、每张候选数（1–4，默认 1）、并发数。
- 顶部显示"共 X 套、Y 张任务、Z 次生成、预计约 ¥W"，点"开始"后即开始生成。这是整批唯一一次确认。
- 可以只勾选部分套开始，也可以之后追加。

### 3.3 生成

- 并发数可设置，默认 5，上限 10。遇到服务商限流时自动降低并发、延后重试，不会导致重复计费。
- 生成顺序按套进行：优先把已经开始的套做完，让整套尽早可以判断。
- 每行实时显示进度（排队 / 生成中 / 已完成 / 失败及原因）。
- 失败的任务显示原因，可以单独重试，也可以整批"重试所有失败"。
- 生成中可以暂停和继续。进程崩溃或关机后重新打开，继续未完成的任务：已经提交给服务商的任务只继续取结果，不会重新提交。

### 3.4 判断

一套的所有任务都有结果后，这一行进入"待判断"。判断和其他套的生成同时进行。

- **按套判断，默认通过**：在一行上按 `Enter` 表示整套通过，这套里未被标记的图全部采用。
- **标记例外**：选中某张图后按 `R` 重出，或按 `X` 不交付。
- **生成失败的图**：同样可以按 `X` 标记不交付；一套里的失败图全部标记不交付后，这套可以整套通过，失败图不进入 `成图/`，也不计入"失败 d 张"与"重试所有失败"。还有未处理的失败图时，整套通过提示"有生成失败的图，请重试或标记不交付"。撤销可恢复为失败状态。（2026-09-25 修订）
- **多候选**：候选数大于 1 时，用数字键在同一任务的候选之间选择；不选则默认采用第一张。
- **重出**：按 `R` 后弹出问题标签（颜色偏、多了配饰、少了单品、下装被换、姿势变了、人物变了、角色互换、其他），数字键多选，可补一句文字。确认后立即排队重出，不需要再授权。新结果回到同一格，历史版本保留、可切换。
- **对照**：选中一张图时，服装裁后图、模特原图、成图三栏同屏并排显示，可同步放大查看局部。
- **导航**：`↑`/`↓` 切换套，`←`/`→` 切换同套内的图；判断完一套自动跳到下一套待判断的行。
- **撤销**：`Cmd+Z` 撤销最近的判断操作；已交付的套可以"撤回交付"并重新判断。
- 顶部显示整批进度："已交付 a 套 / 待判断 b 套 / 生成中 c 套 / 失败 d 张"。
- 页面上的判断直接写入运行记录，没有"保存"与"应用"两个步骤。

### 3.5 交付

- 一套判断完成（每张图都已采用或已标记不交付，且没有排队中的重出）后，自动发布到 `<素材根目录>/成图/<款号>/`。
- 已有同名文件不覆盖，自动加后缀；内容相同的文件不重复写入。
- 撤回交付只改变本批记录，不删除 `成图/` 里已经写出的文件，只在页面上提示。
- 整批结束时生成一份交付总览页（每套一行缩略图，外加映射表），可以直接发给同事。

## 4. 界面原则

- 判断颜色是核心任务。图片区域使用中性灰背景，图片上方和四周不使用半透明模糊或彩色渐变。
- 图片是页面的唯一主角：界面元素少、线条细、按钮克制。
- 全部判断操作都可以只用键盘完成，鼠标操作等价可用。
- 桌面宽度优先（≥1280px），不做手机版。
- 具体视觉稿与用户共同迭代确定，不在本 spec 内定稿。

## 5. 保留的运行保障

- 同一任务的一次生成只会被提交一次，崩溃恢复不重复提交、不重复计费。
- 所有生成版本都保留，不覆盖；采用哪个版本只能由人的判断改变。
- 运行记录原子写入，异常退出后可以恢复；同一批同一时间只允许一个运行进程。
- 密钥不写入页面、日志或交付物。

## 6. Out of Scope

- AI 自动质检、质检打分或排序（明确不做）。
- 逐步指纹授权、dry-run、review-selection 文件、一次性审核会话（整体删除）。
- local-drift 本地漂移检测、经典版 / 玻璃版两套报告模板（删除）。
- 旧版图解使用说明（`fashion-tryon-usage-guide.html`、截图与 PDF 导出脚本）删除；使用说明只保留 `docs/USAGE.md`，同事安装包与测试反馈模板按本 spec 的看板流程描述。（2026-09-25 修订）
- 素材风险自动评分、自动姿势配对（本版不做，配对按目录与顺序确定）。
- 遮罩 / 局部编辑，只做整图重出。
- 旧版本运行目录的迁移或兼容读取。
- 多人同时协作同一批、远程访问、手机端。
- 预算上限闸门（只显示预计与已用费用，不拦截）。

## 7. 验收标准

用假服务商（可配置延迟与失败率）和真实目录结构验证：

1. **规模**：40 套 × 7 张的一批，页面在 1 秒内完成首屏渲染，滚动与键盘切换无明显卡顿。
2. **三种模式**：固定服装、一对一、固定模特各准备一组样例，产出的任务数与配对关系符合第 2 节；素材不全的组被单独标出，不影响其他组。
3. **边生成边判断**：第一套完成后，在其余套仍在生成时即可判断并交付这一套。
4. **纯键盘**：只用键盘完成一批 40 套的判断（含至少 3 次重出和 2 次不交付），全程无需使用鼠标。
5. **默认通过**：一套 7 张全部没问题时，只需一次按键即可完成这套的判断与交付。
6. **重出**：标签重出后新结果回到原格，旧版本可切换查看，采用的是用户最后选择的版本。
7. **并发与限流**：并发设为 10 时，同时进行中的任务不超过 10；模拟限流时自动降速，最终全部完成，且无任何任务被重复提交。
8. **崩溃恢复**：生成中强制结束进程，重新打开后状态完整，已提交的任务只取结果不重提，已做的判断不丢失。
9. **交付**：通过的套出现在 `成图/<款号>/`，重复交付不覆盖已有文件；不交付和未采用的版本不进入 `成图/`。
10. **只读输入**：整批运行前后，素材目录中除 `成图/` 以外的文件字节不变。
11. **真实服务商冒烟**：用 apimart 真实跑 2 套（每套 3 张），全流程走通。
12. **失败图不交付**：一套中有图生成失败时，把失败图标记不交付后整套通过，`成图/` 只有其余成功的图；撤销后这套恢复为有失败、不能通过。（2026-09-25 修订）
13. **准备失败可重试**：未开始的套准备失败时，该行显示失败摘要；点"重新准备"后重新裁切与生成提示词，成功后可以勾选开始。（2026-09-25 修订）

## 8. 待决事项
