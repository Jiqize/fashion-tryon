# Try-on MCP：出图工具化与只读节点图

- 状态：已确认（2026-10-15）
- 日期：2026-10-15
- 基于：精简流程 `run` / `crop`（2026-10-14、10-15 实现并经 8 款 33 张新素材测试）
- 不取代：Tryon Studio spec（studio 看板保留原样，本 spec 不涉及）

## 1. 背景与目标

现在 Agent 通过 skill 调 CLI 出图：先看服装图写裁切方案、执行 `crop`，再在后台跑 `run`，等它结束后把报告路径交给用户。存在的问题：

- 每个 Agent 都要读 skill 才知道命令、参数和输出格式，换一个宿主（Codex CLI）要再教一遍。
- `run` 一次要几十分钟（Codex 出一张图 2–3 分钟），中途只能看 stderr 的日志行，无法回答“现在到哪了”。
- 出图过程不可视：结束前看不到哪些款已出、哪些在排队、哪张失败。

目标：

1. 把精简流程包成一个本机 MCP 服务，Claude Code 与 Codex CLI 装上即可调用，不需要再读 skill 就能完成“扫描 → 裁图 → 出图 → 查进度”。
2. 出图在后台进行，Agent 随时可以查进度、取消，宿主会话结束不影响已开始的出图。
3. 每次出图有一张只读节点图网页，边跑边更新，用户直接看到每张图走到了哪一步。

这一阶段的节点图只能看，不能编辑；后续的“可编辑节点编辑器”另立 spec。

## 2. 安装与宿主

- MCP 服务随 `fashion-tryon` 一起安装，以本机 stdio 方式运行，由宿主按需启动，不监听任何网络端口。
- 提供 Claude Code 与 Codex CLI 的一行注册命令（写入安装说明）；不提供 Claude Desktop、DSH、MindFrame 的接入说明。
- skill 保留，作为同事日常入口；skill 里补一句“装了 MCP 时优先用 MCP 工具”。CLI 的 `run` / `crop` / `studio` / `status` 行为不变。

## 3. 工具

共六个工具。所有工具的返回都是结构化结果（成功的数据或带错误码和中文说明的错误），文件路径一律给绝对路径，便于宿主 Agent 直接打开图片。

### 3.1 扫描素材 `scan`

- 输入：素材根目录。
- 返回：每款的款号、服装图列表、模特图列表、`裁图/<款号>/` 里已有的裁图列表，以及缺服装图或缺模特图的款的提示。
- 支持的两种目录结构、款号取法、忽略 `成图/` 与系统伴生文件，均与现有 `run` 一致。
- 只读，不写任何文件。

### 3.2 裁图 `crop`

- 输入：素材根目录、裁切方案（直接作为参数传入，格式与现有 `crop --plan` 的 JSON 相同）、是否替换已有裁图。
- 行为与现有 `crop` 命令完全一致：裁图写到 `<素材根目录>/裁图/<款号>/`，不替换时已有裁图保留。
- 返回：每款写出的裁图绝对路径，供 Agent 逐张打开检查。
- 工具说明里写明裁切方案的挑选规则（每款 4–5 张：全身-正面、半身-正面各一张不裁，2–3 张细节，有背面/侧面图时加上），这样宿主不读 skill 也能做对。

### 3.3 开始出图 `start_run`

- 输入：素材根目录；可选的换装范围（`outfit` 默认 / `top`）、款号列表、每款最多参考图数（默认 6）、引擎（`codex` 默认 / `apimart`）。
- 调用后立即返回（不等出图结束）：runId、run 目录、节点图页面路径、本次计划出图的张数。
- 出图在独立的后台进程中进行，宿主会话结束、MCP 服务退出都不会中断它。
- 出图内容、参考图选取、提示词、交付到 `成图/<款号>/`、从不覆盖已有文件（加 `-v2`、`-v3`）、报告页 `report.html`，全部与现有 `run` 一致。
- 开始时自动在浏览器打开节点图；输入里可以关掉。
- 同一素材根目录同一时间只允许一个出图在跑：已有出图在跑时，直接拒绝并返回正在跑的 runId，不排队。
- 引擎选 `apimart` 会产生真实费用：工具说明写明只有用户明确要求时才用；缺密钥时在出图开始前报配置错误。
- 款号不存在、没有任何可出图的款时，在开始前报错，不创建 run。

### 3.4 查进度 `run_status`

- 输入：素材根目录与 runId；不给 runId 时取这个素材根目录最近一次 run。
- 返回：
  - 整体状态：进行中 / 已完成 / 部分失败 / 已取消 / 已中断（见 §5）。
  - 计数：计划张数、已完成、失败、排队中、跳过的款数，已用时间。
  - 当前正在出的那张（款号与模特图名）。
  - 每款每张的状态；已完成的给成图与交付路径，失败的给原因。
  - 节点图与报告页路径。
- 只读，进行中也能查。

### 3.5 取消出图 `cancel_run`

- 输入：素材根目录与 runId。
- 行为：立即停止；正在出的那张放弃（不写入 `成图/`），已经交付的图保留不动，未开始的标为“已取消”。整体状态变为“已取消”，节点图与报告页随之更新。
- 对已结束的 run 调用时，返回它当前的状态，不报错。

### 3.6 历史出图 `list_runs`

- 输入：素材根目录。
- 返回：`成图/_runs/` 下每次出图的 runId、开始时间、参数（换装范围、款号、引擎）、整体状态与计数、节点图和报告页路径，按时间倒序。
- 只读。现有格式（本 spec 之前）的 run 也要列出，缺失的字段留空。

## 4. 节点图

每次出图在 run 目录生成一页本地只读网页，打开即可查看，不需要启动服务。

- 布局：每款一条横向泳道，从左到右依次为
  1. 服装参考图节点（裁图或原图，标明来源和用途名）；
  2. 提示词节点（显示换装范围，点开看全文）；
  3. 每张模特图一组“模特图 → 成图”节点。
- 每个成图节点显示状态：排队 / 生成中 / 已完成 / 失败（附原因）/ 已取消；已完成的显示成图缩略图和交付的文件名。
- 页面顶部显示参数、整体状态、进度（已完成 / 计划张数）与已用时间；有跳过的款单独列出原因。
- 出图进行中，页面每隔几秒自动刷新进度，不需要手动刷新，也不跳回顶部；出图结束后停止刷新。
- 点任意图片可放大查看；放大时原图与成图并排。
- 只读：没有通过、重出、删除等任何操作按钮。
- 视觉沿用现有报告页的中性灰底色；节点之间的连线细而克制，不使用彩色渐变和半透明模糊。
- 节点图只依据 run 目录里的运行记录（`run.json`）显示；运行记录在开始出图时就写入全部计划的款与图，因此第一张还没出完时，整张图的结构已完整可见。
- 现有的 `report.html` 保留，结束后照旧可用。

## 5. 运行记录与异常

- 运行记录 `run.json` 需要增加：本次参数、整体状态、开始与结束时间、每张图的状态。每张图状态变化后立即写盘（原子写入）。
- 出图进程意外退出（被强杀、关机）后，记录里仍显示“进行中”的 run，在查进度、列历史、节点图中显示为“已中断”，并释放同一素材根目录的出图占用，可以重新开始出图。
- 已中断的 run 不自动续跑；需要补出的款，由 Agent 用 `start_run` 指定款号重新开始（已交付的图不会被覆盖）。
- 密钥不出现在工具返回、运行记录、节点图和日志中。

## 6. Out of Scope

- 可编辑节点编辑器（改参考图、改提示词、单张重出），下一阶段另立 spec。
- 人工判断、通过、交付决定：精简流程本来就是出完直接写入 `成图/`，本阶段不改。
- 通过 MCP 启动或操作 studio 看板。
- 自动质检、打分（明确不做）。
- 已中断 run 的自动续跑、同一素材根目录多个 run 并行或排队。
- 网络传输的 MCP（HTTP/SSE）、远程访问、Claude Desktop / DSH / MindFrame 接入。
- 修改出图效果相关的提示词、参考图规则与引擎行为。

## 7. 验收标准

全部用假引擎（可配置每张耗时与失败）验证，真实引擎只做最后一条冒烟。

1. **注册**：按安装说明在 Claude Code 与 Codex CLI 中各注册一次，宿主中能看到六个工具。
2. **扫描**：两种目录结构各一份样例，`scan` 返回的款号、服装图、模特图、已有裁图与现有 `run` 的扫描一致；缺图的款带提示。
3. **裁图**：同一份方案经 `crop` 工具与 CLI `crop --plan` 产出的裁图字节一致；不替换时已有裁图不变。
4. **后台出图**：`start_run` 在 2 秒内返回；随后结束 MCP 服务进程，出图继续直到完成，`成图/` 中的结果与直接跑 CLI `run` 一致。
5. **进度**：出图进行中多次调用 `run_status`，已完成张数单调递增，并能指出当前正在出的那张；结束后状态为“已完成”或“部分失败”，计数正确。
6. **单占用**：同一素材根目录出图进行中再调 `start_run`，被拒绝并返回正在跑的 runId；换一个素材根目录可以同时开始。
7. **取消**：出图中途 `cancel_run`，1 个出图周期内进程结束；已交付的图保留，正在出的那张不进入 `成图/`，其余标为已取消。
8. **中断**：出图中途强杀后台进程后，`run_status` 显示“已中断”，同一素材根目录可以重新 `start_run`。
9. **节点图**：开始后立即打开节点图，能看到全部款和全部计划的图（排队状态）；进行中自动刷新，各节点状态与 `run_status` 一致；结束后停止刷新。8 款 33 张规模下首屏 1 秒内显示完。
10. **历史**：`list_runs` 按时间倒序列出本 spec 前后产生的 run，旧 run 缺失字段留空，不报错。
11. **不覆盖**：同一款重复出图，`成图/` 里已有文件字节不变，新图为 `-v2`、`-v3`。
12. **只读输入**：整个过程前后，素材根目录中除 `成图/`、`裁图/` 以外的文件字节不变。
13. **无密钥泄漏**：用 apimart 假配置跑一次，工具返回、`run.json`、节点图、日志中均不含密钥。
14. **真实冒烟**：在 Claude Code 中只用 MCP 工具，对一份真实素材（2 款、各 2 张模特图，Codex 引擎）完成扫描、裁图、出图、查进度，节点图正常显示。
