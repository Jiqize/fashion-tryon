# Fashion Try-on Runner v3 Spec：付费前视觉预检与人工定稿交付

**状态：** 已由用户于 2026-08-31 确认；本文是 v3 阶段的行为事实来源。
**范围：** 在现有本地 CLI + Agent Skill + 离线报告架构内，增加正式生图前的可视计划确认，以及生图后的采用版本、返工基线和最终交付闭环。
**基线：** v1、v2 与 v2.1 已交付行为继续有效；本文件确认后补充并局部覆盖既有 spec。

## 背景与目标

当前流程已经能完成引导式 preflight、批量生成、人工 pass/redo、受控返工和本地漂移提醒，但还存在两个断点：

1. 用户在正式生图前主要看到文字任务数，不能直观看到服装与模特如何配对、实际将使用什么裁切、哪些任务可能有风险。
2. 新版本生成后会成为当前候选，但“最新候选”“人工采用版本”和“下一次返工基线”没有分开；一个局部修好但整体变差的新版本可能顶掉原本更好的版本，最终交付也缺少明确产物。

v3 要形成一个前后闭合的安全流程：

~~~text
素材与回答
  → 离线视觉预检
  → 用户确认同一份计划快照
  → 正式生图
  → 候选与采用版本比较
  → 从明确基线返工
  → 人工定稿
  → 生成可追溯交付包
~~~

## 关键行为

### B1 保持现有架构与信任边界

- CLI 继续是唯一执行 Interface；Agent Skill 只转述 CLI 结果并调用 CLI，不复制计划、版本选择、交付或成本逻辑。
- `manifest.json`、`state.json`、`review.json` 与 `events.jsonl` 继续是运行事实；视觉预检 HTML、审核报告、浏览器草稿和交付目录都是可重建派生物。
- 报告与预检页面不得直接调用 provider、修改 run JSON 或把 localStorage 当作运行事实。
- 输入素材保持只读；prepared、生成版本、预检资产和交付物只写入 run 目录。
- 所有远程生成仍需当次明确授权；首次生成授权不能覆盖 retry，retry 授权也不能覆盖新的首次生成。

### B2 完整解析后先生成视觉预检

- guided questions 全部解决后，系统先进入“待视觉确认”，不得直接开始正式生图。
- 系统生成可直接以 `file://` 打开的离线 `preflight.html`；不依赖服务器、网络字体、CDN 或运行中的前端。
- 视觉预检至少展示：
  - 服装与模特配对矩阵，以及稳定的任务编号和款级分组。
  - 每个任务的 scope、配对方式、输出比例、review mode 和实际解析后的模型标识。
  - 将用于正式生成的服装与模特工作副本；服装有可信裁切时显示裁切结果，没有可信裁切时明确显示“使用全图回退”。
  - 首轮任务数、理论最高生成次数和输出位置。
  - skipped、uncertainties、缺失角色、数量不匹配、精确重复图片、裁切回退和其他会影响结果的风险。
- “疑似配错”必须标为需要人工确认的提示，不能伪装成确定错误。
- 生成视觉预检本身不得调用生图 provider，也不得为了丰富页面额外调用远程视觉模型；无结构目录原本必需的角色分类行为维持既有合同。
- 页面展示的工作副本必须与获批后正式生成使用的字节一致；若无法继续复用或确定性重建同一字节，原确认失效。

### B3 计划快照与付费授权绑定

- 每份已解析视觉预检都有稳定的计划摘要和计划指纹。
- 计划指纹至少绑定：输入内容指纹、任务与配对、scope、裁切工作副本、输出比例、模型、review mode、自动重出上限和最高生成次数。
- 用户授权必须明确指向当前计划指纹；Agent 在请求授权时同时给出预检路径、首轮任务数和理论最高生成次数。
- 缺少确认、确认指向旧计划、输入发生变化、回答或预设变化、任务/模型/比例/裁切/成本变化时，CLI 必须在构造生图 adapter 或产生 provider 调用前拒绝执行，并要求重新生成和确认预检。
- 同一已确认计划在进程中断后可以 resume；只要计划和输入未变化，不要求为恢复已授权的首轮任务重复确认。
- 历史 run 的 report、resume 和 retry 保持可用；尚未开始执行的旧 run 不能绕过 v3 的首次生成确认。

### B4 安全预设

- 用户可以显式选择命名预设，例如“ELLE 全身 / 3:4 / manual”，减少重复回答。
- v3 安全预设只允许保存 `scope`、`pairing`、`size` 和 `reviewMode`；不得保存密钥、输入/输出路径、人工自由文本、provider 请求、模型 ID 或自动重出上限。
- 预设不自动套用“上次使用值”；必须由用户或 Agent 当次显式选择。
- 预设值无效、与素材数量冲突或不能解决现有问题时，preflight 继续返回问题，不能静默改值。
- manifest 和视觉预检必须展示全部最终解析值及其预设来源；预设不能形成隐藏参数。

### B5 分离候选、采用版本与返工基线

- 每个任务分别表达：
  - 当前候选版本：最新生成、等待人工判断的版本。
  - 人工采用版本：用户目前认可的最佳版本；可以为空。
  - 返工基线：下一次受控返工明确从哪个既有版本继续。
- 生成新候选不得自动取消或替换已经采用的版本。
- 用户可以把任意仍完整存在的历史版本设为采用版本，也可以取消采用；所有旧版本继续不可覆盖、不可删除。
- 用户可以从任意历史版本发起受控返工，不要求它必须是最新候选；返工 selection 必须显式绑定该基线版本。
- 新候选生成后，系统同时保留基线、既有采用版本和新候选；是否改为采用必须由用户再次决定。
- 历史 v1/v2/v2.1 run 读取时，把原 `selectedVersionId` 解释为当前候选，但不得自动推断为人工采用版本，也不得为了兼容而改写原文件。

### B6 报告中的版本比较与人工决策

- 报告在任务总览中分别显示“当前候选”和“已采用”，不能再用一个标签混合表达。
- 用户至少可以比较当前候选与采用版本，并可从历史中选择其他两个版本比较。
- 比较视图提供同位置对照能力，至少支持同步缩放/平移和拖动分割对比；已有本地漂移证据继续作为辅助信息，不冒充人工质量结论。
- 每个历史版本提供清楚的“设为采用版本”“作为返工基线”和“参与比较”动作；动作先进入浏览器草稿，不直接写 run 事实。
- 浏览器 v3 草稿按 run 隔离，并能原子读取和迁移兼容的 v2 草稿；旧草稿不删除。
- 当前候选变化时，只使绑定旧候选的未提交决定过期；已经写入 run 事实的采用版本不随之消失。
- 报告可筛选未检查、已采用、待返工、不交付、漂移越界和生成异常，并显示距离可交付还缺多少任务。

### B7 人工决定 artifact 与原子应用

- 报告导出严格版本化的 v3 人工决定 artifact；它可以表达采用某个历史版本、从指定版本返工，以及明确不交付某个任务。
- 不交付必须是用户显式决定，不能由生成失败、AI verdict、筛选状态或缺失图片自动推断。
- artifact 只包含本次已判断任务；未检查任务不能伪装为通过、采用或不交付。
- CLI 在写入运行事实前整体验证 schema、run、task、version 所有权、版本 hash 和重复项；任一错误都不得部分应用。
- 应用采用、取消采用和不交付决定不调用 provider；返工仍先返回精确任务数与最高调用数，再等待独立付费授权。
- v1/v2 retry selection 继续按原语义可读；旧 selection 中的 `pass` 不自动升级为 v3 的正式采用决定。
- 人工自由文本继续按不可信数据处理，不进入 HTML、命令、审计或 prompt 的控制位置。

### B8 定稿条件与交付包

- 默认只有当每个可运行任务都已经采用一个完整版本，或被用户显式标记为不交付时，run 才达到“可定稿”。
- 未检查、待返工、采用版本缺失/损坏或未明确处理的生成异常都会阻止默认定稿，并返回完整阻塞清单。
- 定稿不调用 provider，不修改或覆盖任何图片版本。
- 每次成功定稿创建一个新的、不可覆盖的 delivery 版本；后续改变采用决定后再次定稿，会产生新的 delivery，旧 delivery 保留。
- delivery 至少包含：
  - 只由本次采用版本组成的最终图片目录。
  - 机器可读的任务、素材、采用版本、文件 hash 和不交付项映射。
  - 便于业务使用的 CSV 映射。
  - 可离线打开的最终 contact sheet。
- 最终图片使用稳定、可读且冲突安全的文件名；映射中不得泄漏密钥、Authorization、完整远程响应或不必要的绝对私人路径。
- delivery 是运行事实的派生物；删除后可由同一采用决策重建，不能反向成为 resume/retry 的状态来源。

### B9 Skill 与用户主路径

- 用户仍可只提供一个结构化目录，或“服装目录 + 模特目录”，并回复“按推荐”或选择一个安全预设。
- Agent 在问题解决后先返回 `preflight.html`、计划指纹、任务数与最高调用数；只有用户确认该快照后才开始正式生图。
- 生图后 Agent 返回人工报告；用户可完成采用、返工基线和不交付决定，再导出 artifact 交给 Agent。
- Agent 先应用无付费决定；若含返工，再 dry-run、报告调用上限并取得新的授权。
- 全部任务处理完成后，Agent 执行定稿并返回本次 delivery 目录、最终 contact sheet 和交付数量。
- 普通用户不需要手写计划指纹、任务 ID、版本 ID 或完整 CLI 参数；Skill 从 CLI 结构化结果中传递这些值。

## Out of Scope

- Seedream 5 Pro、Wan 或其他新生图/编辑 adapter；v3 不新增 provider seam。
- 真正的蒙版编辑、框选编辑、inpainting、OCR、小字修复和自动语义分割。
- AI 自动采用、自动不交付、漂移后自动重出或任何没有当次授权的新增付费调用。
- 报告直接写本地 run 文件、直接调用 CLI/provider，或把 localStorage 作为运行事实。
- 云端同步、账号、多人审批、远程服务、MCP server 或重新建立 DSH 工作台。
- 素材库、通用资产管理、可视化修图器和任意工作流表单引擎。
- 自动把历史 pass、AI pass 或 selected version 推断成正式采用版本。

## 验收标准

1. guided 问题解决后先生成离线 `preflight.html` 并停在待确认状态；fake image provider 调用数为 0。
2. 40 个任务的预检在桌面与窄屏可查看全部配对、scope、比例、模型、裁切/全图回退、任务数、最高调用数和风险，打开页面产生零网络请求。
3. 页面展示的 prepared 工作副本与获批后正式生成读取的文件 hash 一致；文件无法复用或输入变化时旧确认失效。
4. 内容相同的重复图片、跳过文件、数量不匹配、缺失角色和裁切回退都有明确提示；“疑似配错”不表达为确定事实。
5. 安全预设只能包含四个允许字段，必须显式选择；最终 manifest/预检展示全部解析值，非法或冲突预设在生成前拒绝。
6. 确认当前计划指纹后，fake manual run 恰好按首轮任务数调用生图；缺少、错误或过期指纹时在 provider 构造和调用前失败。
7. 修改任一输入字节、回答、配对、scope、比例、模型、review mode、裁切或调用上限都会使旧确认失效；未变化的中断 run 可 resume。
8. 任务已有采用版 v01 后生成 v02，v01 仍保持采用；报告分别展示 v01 与 v02，且可同步比较。
9. 用户拒绝 v02、从 v01 返工得到 v03 时，v01、v02、v03 全部保留，返工控制记录的基线准确，provider 只被调用一次。
10. v3 artifact 可原子应用采用、取消采用、指定返工基线和不交付；跨 run、未知 task/version、损坏版本、重复任务或部分无效时运行事实完全不变。
11. 应用纯采用/不交付决定和定稿时 provider 调用数为 0；含返工时仍先 dry-run 并重新取得授权。
12. 候选变化只使对应浏览器草稿过期，不删除已经持久化的采用版本；v2 草稿可迁移且旧 key 保留。
13. 未检查或未明确处理的任务阻止默认定稿并返回完整清单；全部任务采用或显式不交付后可定稿。
14. 两次定稿产生两个不可覆盖 delivery；每个 delivery 的图片、JSON/CSV 映射、hash 和 contact sheet 与当时采用决定一致，删除后可重建。
15. 历史 v1/v2/v2.1 run 可重建报告、resume 和 retry，原 selected version 不自动成为采用版本，读取过程不修改历史 JSON 字节。
16. fake E2E 覆盖“guided → 视觉预检 → 计划确认 → 首轮生成 → 采用 v01 → v02 返工失败 → 从 v01 生成 v03 → 采用 v03 → 定稿交付”，并精确断言所有 provider 调用次数。
17. 所有普通测试使用 fake adapter 和本地合成图；HTML、JSON、CSV、events、tracked files 和 delivery 通过秘密与绝对私人路径检查。
