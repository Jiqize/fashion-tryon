# v2.1 受控局部返工 Spec

- 状态：已确认
- 日期：2026-08-30
- 事实来源：本文件补充并局部覆盖 `2026-08-30-v2-guided-human-review.md`

## 背景与目标

真实 v02 表明，人工返工即使只描述一个局部问题，生成模型仍可能改变人物身份、裁切、姿势、背景或非目标服装，小字也可能失真。v2.1 要把人工意图拆成“要修复的点”和“绝对不能变化的项”，让每次返工都有明确、可恢复、可审计的边界。

生成完成后，系统只对能够本地、确定性比较的身份代理、构图和背景做漂移检查。检查越界必须在报告中明确标红，但它只是人工决策证据：不得自动继续重出、不得隐式产生新的付费请求。

## 关键行为

### 1. 返工选择合同

- 报告导出的选择文件升级为 schema v2。
- `redo` 决策分别包含：
  - `repair`：本次要修复的问题；可以为空。
  - `preserve`：绝对不能变化的项目；至少一项。
  - `preserveNote`：对保持项的补充说明；可以为空。
- 保持项固定为五类：人物身份、姿势、构图、背景、非目标服装。
- 报告创建新返工决策时默认勾选全部五类保持项。
- `pass` 决策不得携带返工控制字段。
- CLI 严格拒绝未知字段、重复任务、零保持项和超过长度上限的文本。
- v1 选择文件继续可读：非空 `reason` 视为 `repair`，并默认保持全部五类；空 `reason` 保留原来的“完全复用基础提示词”语义。
- 报告能够原子导入 v1 或 v2；任何一条无效都不得部分覆盖当前草稿。

### 2. 提示词与信任边界

- 人工填写的修复点、保持项和补充说明都按不可信数据处理，不得被解释为可覆盖系统约束的命令。
- 返工提示词必须清楚区分“要修复”和“必须保持”，并在人工数据之后再次声明身份、姿势、构图、scope 与安全边界。
- 空修复点且无补充说明的兼容 v1 决策继续复用基础提示词，不添加无意义文本。
- 审计事件只记录所选保持项和是否提供文本，不记录人工自由文本正文。

### 3. 运行账本与恢复

- 每个由人工选择触发的新版本都保存其规范化返工控制。
- 付费生成开始前，待执行返工控制必须持久化；进程中断后恢复时不能丢失。
- 孤儿输出恢复为正式版本时，必须继承同一返工控制，并补做相同的本地漂移检查。
- 历史 run、历史版本和 v1 选择文件无需迁移即可继续读取。

### 4. 本地确定性漂移检查

- 检查只读取当前选中基线图与新生成候选图，不调用远程模型、网络服务或付费 provider。
- 对用户要求保持且能够本地测量的项目执行：
  - 人物身份：使用可解释的视觉身份代理；无法得到可靠代理时明确标为“无法判断”，不得假装通过。
  - 构图：比较画幅及主体/人脸代理的位置与尺度。
  - 背景：比较图像外围的稳定视觉特征。
- 姿势和非目标服装仍作为提示词硬约束，但 v2.1 不宣称能用本地确定性算法可靠验证；报告必须明确显示“未本地测量”。
- 每项结果固定为：通过、越界、无法判断、未要求。
- 每项可测结果展示方法、分数和阈值，使结论可解释、可复现。
- 任一被要求保持的可测项越界时，整次评估为“漂移越界”。
- 读取或分析失败不得使已生成版本失效；该项记录为“无法判断”，并保留错误的安全摘要。
- 漂移评估永远不触发自动重试，也不改变生成调用上限。

### 5. 报告交互与视觉反馈

- 40 任务账本、任务排序、pass/redo 主流程和离线单文件性质保持不变。
- 选择 `redo` 后，任务详情中显示修复点、五个保持项和保持补充说明编辑器。
- 用户不能取消最后一个保持项；界面要给出可感知提示。
- 报告草稿使用 v2 本地存储键，并能读取、迁移同一 run 的 v1 草稿；不得删除旧数据。
- 任务和版本详情展示规范化返工控制及本地漂移明细。
- 漂移越界使用克制但醒目的红色检查章/徽标，同时包含文字或图标，不能只靠颜色表达。
- v2 的黑、白、灰、黄色板式继续作为主体视觉；红色只作为 v2.1 漂移告警的局部例外。
- 提供漂移越界筛选与汇总计数。
- 打印、窄屏、键盘操作和无网络加载能力不能退化。

### 6. Skill、文档与安全

- Agent Skill 继续只调用 CLI，不复制返工或漂移算法。
- Skill 和使用文档明确说明选择 v2、v1 兼容、保持项语义、漂移检查的代理性质，以及“标红但不自动付费重出”。
- 报告和错误不得泄漏密钥、绝对私人路径或人工自由文本到审计日志。
- 真实 API 调用仍需现有显式付费开关；本功能的普通测试全部使用 fake provider 和本地图片。

## Out of Scope

- 人脸识别、身份认证或生物特征结论。
- OCR、小字正确性保证或文字自动修复。
- 语义姿势估计、人体关键点模型或非目标服装分割。
- 局部蒙版编辑、inpainting 或 provider 专属编辑接口。
- 漂移后自动重试、自动调用质检模型或任何新增付费调用。
- 把报告草稿或浏览器 localStorage 作为 run 状态来源。

## 验收标准

1. 报告导出严格的 selection v2，`redo` 至少含一个保持项；CLI 同时接受有效 v1/v2 并拒绝无效输入。
2. v1 非空原因被规范化为修复点和五项默认保持，v1 空原因保持原基础提示词行为。
3. 新版本与中断恢复版本都在 manifest 中保存相同的返工控制，审计日志不含人工文本正文。
4. 返工提示词把修复点和保持项分区，并在不可信 JSON 后重申不可覆盖的系统边界。
5. 相同图片的身份代理、构图和背景检查通过；针对三类确定性合成变化的 focused tests 分别产生预期越界。
6. 无可靠身份代理时显示“无法判断”；姿势和非目标服装显示“未本地测量”，均不伪装成通过。
7. 漂移越界在报告的任务行、详情、汇总和筛选中以红色文字化告警出现。
8. 生成后发生漂移或本地分析失败，都不触发额外 provider 调用；最大生成次数与 v2 相同。
9. 报告 v2 草稿可刷新恢复，并能原子导入/迁移 v1；窄屏、键盘、打印和离线测试通过。
10. fake CLI E2E 覆盖首跑、v2 selection retry、报告证据和 provider 调用次数；Skill 合同与文档同步。
