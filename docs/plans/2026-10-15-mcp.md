# Try-on MCP Implementation Plan

**Goal:** 把精简流程（`run` / `crop`）包成本机 stdio MCP 服务（6 个工具），出图在独立后台进程进行，每次 run 生成一页边跑边刷新的只读节点图。
**Architecture:** 先把 `runSimple` 改成“先写完整计划、逐张更新状态”的运行记录 v2，并加上同一素材根目录的出图占用锁；节点图是 run 目录里的静态页，靠同步写出的 `run-data.js` 轮询刷新。MCP 层（`src/mcp/`）只做参数校验、拉起后台 `fashion-tryon run` 子进程和读运行记录，入口是新 CLI 命令 `fashion-tryon mcp`。
**Tech Stack:** TypeScript、Node ≥20、`@modelcontextprotocol/sdk@1.31.0`（精确版本）、zod 4、sharp、Vitest、Playwright。

## Global Constraints

- Spec：`docs/specs/2026-10-15-mcp.md`（已确认）。行为与验收以 spec 为准；发现 spec 不足先停下问用户。
- 核心模块（`src/simple/`、`src/studio/`、`src/prepare/`、`src/providers/`）不得 import MCP SDK；只有 `src/mcp/` 可以。`src/cli.ts` 对 `src/mcp/` 只能动态 `import()`（仅 `mcp` 命令触发）。
- 只走 stdio，不监听任何端口。
- CLI `run` / `crop` / `studio` / `status` 的现有行为与输出字段保持兼容（只允许新增字段与新增可选参数）。
- `成图/` 内已有文件从不覆盖（`-v2`、`-v3`…，`COPYFILE_EXCL`）；素材根目录中除 `成图/`、`裁图/` 外只读。
- 密钥不得出现在工具返回、`run.json`、`run-data.js`、节点图、`run.log`。所有写入记录的错误文本先经 `redactSecrets`。
- 默认测试全部用假引擎，不产生费用；真实引擎只在 Task 7 冒烟，且需用户当场同意。
- 工具名精确为：`scan`、`crop`、`start_run`、`run_status`、`cancel_run`、`list_runs`。
- 文案：整体状态中文为 进行中 / 已完成 / 部分失败 / 已取消 / 已中断；单张状态为 排队 / 生成中 / 已完成 / 失败 / 已取消。
- 代码注释用中文，标识符英文；新增依赖仅 `@modelcontextprotocol/sdk`。

### Task 1: 运行记录 v2 与锁

**Files:**
- Create: `src/simple/record.ts`、`src/simple/lock.ts`
- Modify: `src/errors.ts`（加错误码、移入 `redactSecrets`）、`src/cli.ts`（改用 `redactSecrets`）
- Test: `tests/simple-record.test.ts`、`tests/simple-lock.test.ts`

**Interfaces:**
- Produces（`src/simple/record.ts`）：
  - `type ShotState = 'queued' | 'generating' | 'done' | 'failed' | 'cancelled'`
  - `type RunStatus = 'running' | 'completed' | 'partial' | 'cancelled' | 'interrupted'`
  - `interface RunParams { swap: SwapMode; skus: string[] | null; maxReferences: number; engine: string }`
  - `interface RunShot { model: string; modelThumb: string; state: ShotState; result?: string; delivered?: string; error?: string }`
  - `interface RunGroup { sku: string; referenceSource: 'crops' | 'originals'; references: { file: string; thumb: string; role?: string }[]; prompt: string; shots: RunShot[]; note?: string }`
  - `interface RunCounts { planned: number; queued: number; delivered: number; failed: number; cancelled: number; skippedGroups: number }`
  - `interface RunRecord { schemaVersion: 2; runId: string; sourceRoot: string; runDir: string; reportPath: string; graphPath: string; engine: string; params: RunParams | null; status: Exclude<RunStatus, 'interrupted'>; pid: number | null; startedAt: string | null; finishedAt: string | null; heartbeatAt: string | null; current: { sku: string; model: string } | null; groups: RunGroup[]; counts: RunCounts }`
  - `RUN_ID_PATTERN = /^\d{8}-\d{6}$/`、`runsDir(sourceRoot: string): string`（= `<root>/成图/_runs`）
  - `countShots(groups: RunGroup[]): RunCounts`
  - `writeRunRecord(record: RunRecord): Promise<void>`（原子写 `run.json`）
  - `readRunRecord(runDir: string): Promise<RunRecord>`（旧格式归一；不存在抛 `NOT_FOUND`）
  - `effectiveStatus(record: RunRecord, isAlive?: (pid: number) => boolean): RunStatus`
  - `listRunRecords(sourceRoot: string): Promise<RunRecord[]>`（按 runId 倒序）
- Produces（`src/simple/lock.ts`）：
  - `interface RunLock { runId: string; pid: number; startedAt: string }`
  - `acquireRunLock(sourceRoot: string, lock: RunLock, isAlive?: (pid: number) => boolean): Promise<void>`
  - `releaseRunLock(sourceRoot: string, runId: string): Promise<void>`
  - `readActiveLock(sourceRoot: string, isAlive?: (pid: number) => boolean): Promise<RunLock | null>`
  - `isProcessAlive(pid: number): boolean`（`process.kill(pid, 0)`，`ESRCH` 为 false，`EPERM` 为 true）
- Produces（`src/errors.ts`）：错误码 `'RUN_IN_PROGRESS'`；`redactSecrets(value: string): string`（规则与现 `redactMessage` 相同：`Bearer xxx`、`sk-…` 打码，截断 400 字）

**Requirements:**
- `run.json` 用临时文件 + `rename` 原子写入（沿用 `store.ts` 的 `writeJsonAtomic` 写法，不跨模块 import 私有函数，可在 record.ts 内复写）。
- 旧格式（无 `schemaVersion`）归一：`runId` 取目录名；`params`、`pid`、`startedAt`、`finishedAt`、`heartbeatAt`、`current` 为 `null`；`graphPath` 仍按 `<runDir>/graph.html` 给出；单张 `state`：有 `result` → `done`，有 `error` → `failed`，否则 `cancelled`；整体 `status`：有失败 → `partial`，否则 `completed`；`counts` 用 `countShots` 重算。
- `effectiveStatus`：记录为 `running` 且（`pid` 为 null 或 `isAlive(pid)` 为 false）→ `interrupted`，否则原样。
- `listRunRecords`：只列 `成图/_runs/` 下名字匹配 `RUN_ID_PATTERN` 且含可解析 `run.json` 的目录；不可解析的跳过不报错；目录不存在返回 `[]`。
- 锁文件：`<root>/成图/_runs/.lock`，内容为 `RunLock` JSON，用 `open(…, 'wx')` 独占创建。已存在且持有进程存活 → 抛 `RUN_IN_PROGRESS`，message 为 `这个素材目录正在出图：<runId>`；持有进程已死或内容不可解析 → 视为陈旧，删除后重取一次。
- `releaseRunLock` 只删除 `runId` 与自己相同的锁；不存在时静默。

**Test cases:**
- 写 v2 记录再读 → 字段完全一致；写盘中途无临时文件残留。
- 读旧格式 `run.json`（取自当前 `runSimple` 输出形状，含 1 成功 1 失败）→ `schemaVersion 2`、状态 `done`/`failed`、整体 `partial`、`params null`。
- `effectiveStatus`：`running` + 存活 pid → `running`；`running` + 死 pid → `interrupted`；`completed` + 死 pid → `completed`。
- `listRunRecords`：3 个 run 目录（含 1 个旧格式、1 个只有 `run.log` 无 `run.json`、1 个名字不匹配）→ 返回 2 条，按 runId 倒序。
- 第一次 `acquireRunLock` 成功；同 root 第二次（isAlive→true）→ `RUN_IN_PROGRESS` 且 message 含第一个 runId；isAlive→false 时第二次成功并覆盖。
- `releaseRunLock(root, 其他 runId)` → 锁仍在；`releaseRunLock(root, 自己)` → 锁删除。
- `redactSecrets('Bearer abc sk-12345678abcd')` → 不含 `abc` 与 `sk-12345678abcd`。

### Task 2: runSimple 改为先计划、逐张状态、可取消

**Files:**
- Modify: `src/simple/run.ts`、`src/simple/generators.ts`、`src/cli.ts`（`run` 命令）
- Test: `tests/simple-run.test.ts`（扩充）

**Interfaces:**
- Consumes：Task 1 全部导出。
- Produces：
  - `SimpleRunOptions` 新增：`runId?: string`（不给则按当前时间生成 `YYYYMMDD-HHMMSS`）、`heartbeatMs?: number`（默认 15000）、`onSave?: (record: RunRecord) => Promise<void>`（Task 3 用来写节点图；默认无）。
  - `runSimple(options): Promise<RunRecord>`（返回类型由 `SimpleRunResult` 改为 `RunRecord`；`SimpleRunResult` 删除，`report.ts` 改用 `RunRecord`）。
  - `createFakeGenerator(options: { delayMs?: number; failOn?: string }): SimpleGenerator`（name `fake`；按 `delayMs` 等待且响应 abort；`outPath` 含 `failOn` 时抛错；否则写 8×12 灰色 PNG）。
  - CLI：`run` 新增 `--run-id <id>`（须匹配 `RUN_ID_PATTERN`，否则 `VALIDATION_ERROR`）；`--engine fake` 仅当环境变量 `FASHION_TRYON_FAKE_ENGINE` 存在时可用（其值为 JSON `{ "delayMs"?: number, "failOn"?: string }`），否则 `VALIDATION_ERROR: Unknown engine: fake`。JSON 输出新增 `runId`、`graph`，`status` 取值 `completed | partial | cancelled`。

**Requirements:**
- 顺序：扫描与款号校验（错误时不建目录、不取锁）→ 取锁 → 建 runDir（`<root>/成图/_runs/<runId>`，若已含 `run.json` → `VALIDATION_ERROR: run 已存在：<runId>`；目录已存在但无 `run.json` 允许，供 MCP 预先放 `run.log`）→ **一次写出完整计划**（所有款、所有单张 `state: 'queued'`，参考图与模特缩略图路径已确定，`status: 'running'`，`pid: process.pid`，`startedAt`，`params`）→ 逐款准备参考图、逐张出图。
- 参考图条目的 `role` 用 `referenceRole(文件名)` 填写（认不出时省略），供节点图显示用途名。
- 跳过的款（缺服装图/缺模特图）在计划里带 `note`，不含单张，计入 `skippedGroups`。
- 单张状态：开始出图前置 `generating` 并写 `current`；成功 `done`（交付逻辑与现有一致）；失败 `failed`，`error` 经 `redactSecrets`。每次状态变化后立即保存。
- 取消（signal abort）：正在出的那张置 `cancelled`、不写入 `成图/`；其余 `queued` 全部置 `cancelled`；整体 `status: 'cancelled'`、`finishedAt`、`current: null`；保存后释放锁并正常返回记录（不再抛 `ABORTED`）。
- 正常结束：有失败 → `partial`，否则 `completed`；写 `finishedAt`、`current: null`；释放锁。任何异常路径（`finally`）都释放锁。
- 心跳：运行期间每 `heartbeatMs` 更新 `heartbeatAt` 并保存；结束时清除定时器。
- 每次保存依次：`run.json` → `report.html`（现有报告，单张未完成显示“排队/生成中”占位）→ `onSave`。
- CLI `run` 被 SIGTERM（已接到 abort）时输出 `status: 'cancelled'`、`ok: false`，退出码 1。

**Test cases:**
- 假引擎 delay 50ms，2 款各 2 张：在第一张 `generate` 被调用时读 `run.json` → 4 张都在、3 张 `queued`、1 张 `generating`、`current` 指向它；结束后 4 张 `done`、`status completed`、锁文件不存在。
- `failOn` 命中 1 张 → 该张 `failed`、`error` 不含注入的 `sk-…` 密钥、整体 `partial`。
- 第 2 张生成中 abort → 第 1 张 `done` 且已交付；第 2 张 `cancelled` 且 `成图/` 中无对应文件；其余 `cancelled`；整体 `cancelled`；锁已释放；函数正常返回。
- 已有锁（存活 pid）→ 抛 `RUN_IN_PROGRESS`，不创建新 runDir。
- 款号不存在 → `VALIDATION_ERROR`，不创建 runDir、不取锁。
- `--run-id bad` → `VALIDATION_ERROR`；`--run-id` 合法且目录已有 `run.json` → `VALIDATION_ERROR: run 已存在`。
- 不设 `FASHION_TRYON_FAKE_ENGINE` 时 `--engine fake` → `Unknown engine: fake`。
- `heartbeatMs: 20`、delay 100ms → 运行中 `heartbeatAt` 至少更新 2 次。
