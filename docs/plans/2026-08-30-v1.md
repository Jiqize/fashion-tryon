# Fashion Try-on Runner v1 Implementation Plan

**Goal:** 交付一个本地文件夹驱动、可恢复、可由 Agent Skill 调用的 AI 批量换装 CLI，并生成结构化账本与静态 HTML 审核报告。
**Architecture:** CLI 是唯一外部 Interface，核心 runner 在进程内完成 preflight、准备、生成、质检、重出与持久化。DashScope/Qwen 和 APIMART 通过内部 ports 接入，测试使用 fake adapters；DSH、浏览器和 MCP 不进入核心。
**Tech Stack:** Node.js 20+、TypeScript、pnpm、Commander、Zod、Sharp、Vitest、tsdown、原生 `fetch`。

## Global Constraints

- 输入目录只读；所有工作副本和产物写到 run 目录。
- 接受 jpg/jpeg/png/webp，单文件最大 64 MiB。
- 目录结构优先；视觉分类置信度低于 0.70、other 或调用失败必须进入 questions。
- 默认 size `3:4`、并发 `5`、maxRetries `1`，maxRetries 允许 `0..3`。
- scope 只允许 `top|bottom|full|full_acc`；pairing 只允许 `pair|fixedModel|fixedClothing`。
- 所有 JSON 状态使用临时文件 + 原子替换；重跑不覆盖旧版本。
- `report.html` 只读且完全可由 JSON/JSONL 重建。
- 密钥只从环境读取，永不进入参数、日志、异常详情、结构化产物或报告。
- 常规测试只使用 fake adapters；真实链路必须同时有用户授权和 `RUN_PAID_E2E=1`。
- 核心不得依赖 DSH、Cordis、React、浏览器存储或 MCP SDK。

## Planned File Structure

- `package.json`、`pnpm-lock.yaml`、`tsconfig.json`、`tsconfig.build.json`、`tsdown.config.ts`：Node/TypeScript CLI 工程与命令。
- `src/contracts.ts`：v1 schema、枚举、结构化文件解析和兼容性检查。
- `src/errors.ts`：稳定错误码与 CLI 退出码映射。
- `src/config.ts`：环境变量和 CLI options 收敛；不暴露密钥。
- `src/ports.ts`：VisionPort 与 ImageGenerationPort 内部 Interface。
- `src/preflight/scanner.ts`：只读扫描、格式/大小/排除规则和文件指纹。
- `src/preflight/classifier.ts`：目录结构优先分类、视觉兜底和 questions。
- `src/preflight/preflight.ts`：分组、配对、成本预览、manifest 与 answers。
- `src/prepare/images.ts`：压缩、裁图、prepared 工作副本。
- `src/prepare/brief.ts`：内容指纹 + scope 缓存和 garment brief。
- `src/prepare/prompt.ts`：四种 scope 的六段式 prompt。
- `src/providers/apimart.ts`：APIMART 生图 adapter。
- `src/providers/dashscope.ts`：DashScope/Qwen 视觉 adapter。
- `src/run/store.ts`：run 目录、原子 JSON、events JSONL 与版本路径。
- `src/run/runner.ts`：共享并发闸门、状态机、生成、恢复与错误隔离。
- `src/review/reviewer.ts`：四维质检和 scope 一致判据。
- `src/review/retry.ts`：自动与选择性重出。
- `src/report/render.ts`、`src/report/template.ts`：静态报告数据与 HTML。
- `src/cli.ts`：五个命令、stdout/stderr 和退出码。
- `skills/fashion-tryon/SKILL.md`：Agent 对话与 CLI 调用说明。
- `tests/`：与上述职责一一对应的 focused tests、fake ports 和合成 fixtures。
