# v2.1 受控局部返工 Interface Plan

- Spec：`docs/specs/2026-08-30-v2.1-controlled-retry.md`
- 状态：执行中
- 日期：2026-08-30

## 固定边界

- CLI/核心模块是唯一运行事实来源；报告只生成/导入选择，不执行业务逻辑。
- 漂移检查是本地、确定性、可解释的人工辅助证据，不是语义视觉质检。
- 漂移越界或无法判断都不会排队、恢复或触发任何 provider 调用。
- 历史 manifest 和 selection v1 必须继续可读。

## 报告设计增量

- **用户与任务**：批量换装操作者在 40 个任务中快速指出局部修复，并声明不可变化项。
- **布局**：保持现有 Swiss 账本密度；返工控制放入展开详情，不增加常驻宽表列。
- **字体与色彩**：沿用现有字体系统及黑白灰黄；新增 `#b91c1c` / 浅红只用于漂移检查章。
- **签名元素**：红色“漂移越界”检查章，带文字与符号，在任务行和详情形成同一语义。
- **响应式**：桌面账本、窄屏卡片、打印视图共享同一状态文字，不依赖 hover 或颜色。

## Task 1 — Selection v2 与规范化合同

**目标**：建立可兼容读取、严格校验且只有一个规范化出口的人工返工合同。

**Interfaces**

- `src/contracts.ts`
  - 导出 `preservationDimensions`、`PreservationDimension`。
  - 导出 `ManualRetryControl` 及其严格 schema；`preserve` 非空且去重，文本长度上限 500。
- `src/review/manual-selection.ts`
  - 导出 selection v1/v2 联合类型和严格 schemas。
  - `parseHumanReviewSelection(input)` 返回保留源 schema 版本的已验证选择。
  - `manualRetryControlFor(decision)` 把 v1/v2 redo 决策转换为唯一的 `ManualRetryControl`；pass 返回 `undefined`。
  - `serializeHumanReviewSelection(selection)` 保持稳定 JSON 输出。

**TDD / Verification**

1. 先增加 v2 有效/无效、重复保持项、pass 多余字段、v1 兼容和规范化红测。
2. 实现最小合同与解析使 focused tests 通过。
3. 运行 manual-selection 与 contracts focused tests、类型检查。

**完成条件**：selection v2 可严格读写，v1 行为无回归，规范化控制可供 runner 与 report 共用。

**Commit**：`feat: add controlled retry selection contract`

## Task 2 — 提示词边界与可恢复返工控制

**目标**：在付费调用前持久化规范化控制，并把它安全地绑定到新版本。

**Interfaces**

- `src/contracts.ts`
  - `TaskState.pendingManualControl?` 保存待执行控制。
  - `TaskVersion.manualControl?` 保存该版本实际使用的控制。
- `src/review/retry.ts`
  - selection redo 使用 `manualRetryControlFor`。
  - 提示词把 `repair` 与 `mustPreserve` 作为不可信 JSON 数据，随后重申不可覆盖约束。
  - 审计事件只记录保持项与文本存在布尔值。
- `src/run/store.ts`
  - 版本写入接口接受可选控制元数据，并与版本原子落盘。
- `src/run/runner.ts`
  - provider 调用前保存 `pendingManualControl`；成功或恢复后写入版本并清除 pending 字段。

**TDD / Verification**

1. 先写 prompt 信任边界、manifest 版本元数据、中断前 pending 和恢复继承红测。
2. 通过公开 retry/runner 接口实现最小行为。
3. 运行 retry、runner、resume/store focused tests 与类型检查。

**完成条件**：新生成和恢复版本都可追溯到同一返工控制，自由文本不进入审计事件。

**Commit**：`feat: persist controlled retry intent`

## Task 3 — 本地确定性漂移评估

**目标**：以一个深模块提供透明、无网络、不会改变执行流的漂移证据。

**Interfaces**

- `src/contracts.ts`
  - 导出四态检查结果与 `LocalDriftAssessment` schema/type。
  - `TaskVersion.localDrift?` 保存评估事实。
- `src/review/local-drift.ts`
  - `assessLocalDrift({ baselinePath, baselineVersionId, candidate, preserve, checkedAt })` 返回带基线版本证据的完整五维结果。
  - 身份、构图、背景返回方法/分数/阈值；姿势和非目标服装返回明确的未本地测量状态。
  - 不抛出普通图像分析错误；无法分析的维度返回安全摘要。
- `src/run/runner.ts`
  - 只对带人工返工控制的新版本和恢复版本评估。
  - 基线固定为该 selection 指向的原选中版本。
  - 评估结果写入版本，但绝不触发 verify、retry 或新 generation。

**TDD / Verification**

1. 用程序生成的本地图像建立 identical、身份代理变化、主体位移/缩放、外围背景变化、无代理与未要求维度红测。
2. 实现并固定可解释阈值；用仓库现有忽略的 v01/v02 证据做一次非付费校准，不把私人路径写入产物。
3. 增加 runner/fake provider 调用次数与恢复路径测试。
4. 运行 local-drift、runner、resume focused tests 与类型检查。

**完成条件**：确定性样例可复现四态结果，失败降级为无法判断，provider 调用次数不增加。

**Commit**：`feat: assess local retry drift`

**TDD / Verification**

**完成条件**：操作者能可靠表达和恢复控制意图，越界信息清晰但不暗示自动处理。
